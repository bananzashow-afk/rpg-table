# RPG Table

Онлайн-платформа для D&D и настольных RPG: **комнаты → мастер/игроки → права видимости → серверные броски → анимированные кубики**.

Первая версия — рабочий каркас. Архитектура рассчитана на расширение (листы, карты, музыка, инициатива и т.д.) без ломки сетевого ядра.

## Возможности v1

- Создание комнаты (создатель = **мастер**) и вход по коду / ссылке-приглашению
- Real-time синхронизация через **Socket.IO (WebSocket)**
- Роли: мастер и игрок
- Видимость бросков: `PUBLIC` · `PLAYER_AND_GM` · `GM_ONLY` (фильтрация **на сервере**)
- Группы бросков, общий / отдельный режим, лимит **20** кубиков
- Кубики D4–D20 с разной формой и 3D-анимацией
- Итог броска считает **только сервер** (криптостойкий RNG)
- Палитра кубиков (localStorage)
- Переподключение по session token после refresh

## Структура

```
shared/     # Общие типы, валидация бросков, события сокетов
server/     # Express + Socket.IO, комнаты, права, броски
client/     # React + Vite + Three.js UI
```

Клиент **не** содержит логики «истинного» результата — только UI и анимация под значения с сервера.

## Быстрый старт

Требования: **Node.js 20+**.

```bash
npm install
npm start
```

Откройте в браузере:

### Постоянный хостинг бесплатно (ПК можно выключить)

**Render Free** — карта не нужна.

1. Аккаунт: [dashboard.render.com/register](https://dashboard.render.com/register) (через GitHub).
2. Залей проект в GitHub.
3. Render → **New → Blueprint** → этот репозиторий (`render.yaml` уже в проекте).
4. Получишь ссылку `https://….onrender.com`.
5. В env выставь `PUBLIC_URL` на эту ссылку и перезадеплой.

Минусы free: после ~15 мин без трафика сервис засыпает (~1 мин на просыпание). Во время игры по WebSocket не спит.

Платный Tunnelmole / Fly «всегда без сна» — не бесплатно. Локальный туннель работает только при включённом ПК.

### Docker

```bash
cp .env.example .env
docker compose up --build
```

Сервис слушает порт `3001` (или `PORT` из `.env`).

## Переменные окружения

См. [`.env.example`](.env.example).

| Переменная | Описание |
|---|---|
| `PORT` / `HOST` | HTTP-сервер |
| `CORS_ORIGIN` | Origin клиента (`*` или список через запятую) |
| `PUBLIC_URL` | Базовый URL для invite API |
| `SESSION_TTL_MS` | TTL неактивных комнат |
| `VITE_WS_URL` | URL сокета; **оставьте пустым** для same-origin |

## Проверка сценариев

1. Создать комнату → стать мастером → скопировать ссылку  
2. Открыть ссылку в другом браузере / инкогнито → войти игроком  
3. Публичный бросок — видят оба  
4. Скрытый бросок игрока (`PLAYER_AND_GM`) — видят игрок и мастер  
5. Скрытый бросок мастера (`GM_ONLY`) — только мастер  
6. Несколько групп: `1D20`, `3D6`, `1D20+3D4`  
7. Лимит 20 кубиков (`+` блокируется)  
8. Refresh страницы — сессия восстанавливается  

## API (кратко)

- `GET /api/health` — healthcheck  
- `GET /api/invite/:code` — метаданные комнаты / invite URL  
- Socket.IO события: см. `shared/src/events.ts`
